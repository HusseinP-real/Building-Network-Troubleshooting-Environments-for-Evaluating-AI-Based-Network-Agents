[GROUND-TRUTH]
Fault location: client_1.
Fault components: (1) its default gateway is the unused 192.168.1.254 instead of
192.168.1.1; (2) its OUTPUT chain drops TCP to 10.0.1.80:8080 under the unique
soft3888-nika92-compound tag. Both faults are independently sufficient to block
the frontend. Gateway-only repair restores direct backend access but not the
frontend; filter-only repair leaves off-subnet routing broken. Other clients
and the application's backend services are healthy. Complete repair requires
both actions. The procedure verifies each partial repair and both repair orders.

[FIX]
On client_1:
set -eu
ip route replace default via 192.168.1.1 dev eth0
if iptables-legacy -C OUTPUT -d 10.0.1.80/32 -p tcp --dport 8080 -m comment --comment soft3888-nika92-compound -j DROP 2>/dev/null; then iptables-legacy -D OUTPUT -d 10.0.1.80/32 -p tcp --dport 8080 -m comment --comment soft3888-nika92-compound -j DROP; fi
Remove only the tagged experimental rule; do not flush unrelated firewall state.

[RECOVERY]
device: client_1
action: restore the gateway and remove the tagged rule
cmd: |
  set -eu
